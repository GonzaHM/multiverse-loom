# Multiverse Loom: アーキテクチャおよびビジネス要件決定記録

## 1. プロダクト概要

* **プロダクト名**: Multiverse Loom（マルチバース・ルーム）
* **コンセプト**: アメコミ映画（MCU・DCなど）の複雑なマルチバース時系列と分岐を視覚的に整理し、ユーザー自身の視聴進捗を管理・共有できるインタラクティブな相関図PWA。
* **ターゲット層**: 複雑なタイムラインの把握や考察を好む熱狂的なアメコミ映画ファン。
* **既存サービスとの差別化**: 単なる縦スクロールのチェックリストではなく、作品間のつながりをネットワークグラフとして可視化し、「視覚的な布教・考察ツール」として機能させる点。

## 2. プラットフォーム戦略

* **提供形態**: PWA（Progressive Web App）ベースのWebサービス。
* **選定理由**:
  * アプリストアのインストールという障壁（フリクション）をなくし、SNSからのURL遷移によるバイラル拡散を最大化するため。
  * 「ホーム画面に追加」機能により、ネイティブアプリに近いフルスクリーン体験とデータ保持を実現可能。

## 3. インフラ・アーキテクチャ構成（GCP）

初期ランニングコストを月額数百円以内（ほぼ無料枠内）に抑えるサーバーレス構成を採用する。

* **フロントエンド/SSR**: SvelteKit
* **コンピューティング**: Cloud Run (`min-instances=0`設定によりアクセスがない状態での課金をゼロ化)
* **エッジキャッシュ**: Firebase Hosting（Cloud Runの前段に配置し、静的アセットや変動の少ないAPIをキャッシュしてバックエンド起動回数を抑制）
* **データベース**: Firestore（ユーザーの視聴進捗等のパーソナルデータ保存用。作品マスターデータはアプリ内に静的保持または長期間キャッシュして無料枠内に収める）

## 4. 開発・運用ワークフロー

AIエージェントプラットフォーム「Google Antigravity」を中心としたモダンな開発体制を構築する。

* **要件定義・戦略策定**: Geminiを活用してビジネスロジックや戦略の壁打ちを行う。
* **開発環境**: Google Antigravity（エージェントファーストIDE）を利用し、AIとのペアプログラミングで実装を高速化する。
* **ソース・ドキュメント管理**: GitHubをプロジェクトのハブとしてコード、インフラ構成、ドキュメント（本ファイルなど）を一元管理し、変更履歴を記録する。
* **IaC（インフラコード化）**: Terraformを用いてGCPリソースをコードとして管理。
* **CI/CD（自動デプロイ）**: GitHub ActionsとWorkload Identity Federation (WIF) を連携させ、メインブランチへのPush時に自動かつセキュア（キーレス）にGCPへデプロイされるパイプラインを構築する。

## 5. マーケティング・SNS拡散戦略

* **プロダクト主導のシェア機能**: ユーザーの視聴進捗を反映した自分専用の相関図を1枚の画像として出力し、ワンタップでX（旧Twitter）へシェアできる仕組みをPWA内に実装する。
* **イベントドリブン運用**: 新作映画の予告編解禁や公開日前夜など、ファンの熱量が局地的に高まるタイミングを狙い、運営アカウントから最適な視聴ルートの相関図を手動でポストする。
* **海外コミュニティへの直接投下**: Redditのマーベル専用サブレディットなどのディープなファンフォーラムへ、開発者目線で直接アプローチして初期のトラフィックを獲得する。

## 6. マネタイズロードマップ

* **初期〜中期（アフィリエイト）**: タイムラインの文脈に沿って、関連する過去作のBlu-ray、原作コミックス、関連グッズなどのAmazonアフィリエイトリンクを配置する。
* **長期（クリエイターエコノミー）**: ユーザー独自の「考察ボード機能」を追加。有益なタイムライン解釈や考察に対して他のユーザーが少額の投げ銭（チップ）を行える仕組みを導入し、プラットフォーム側が決済手数料を徴収するモデルへ移行する。
